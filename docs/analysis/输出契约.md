# 深度报告输出契约

日报和深度专题是两种文档。日报由 `report.py` 每次生成，角色字段是 `daily_change_summary`。深度专题按模板手写，再用本契约做最小校验。校验程序是 `analysis_contract.py`，只检查结构和一小批禁止出现的写法。它不能判断一个推断是否高明。

## 证据模式

文件开头使用一条注释：

```text
<!-- evidence_mode: synthetic -->
```

| 模式 | 何时使用 | 校验额外要求 |
| :--- | :--- | :--- |
| `template` | 空白模板 | 保留占位符，并写明不得伪造 |
| `synthetic` | 用于学习的合成演示 | 出现「合成演示」和「非实测」，保留【缺失】 |
| `measured` | 目录里真有当次截图和 UI 树 | 写明「证据模式：实测」，证据编号使用 `EVD-`，并给出置信度 |

`measured` 不能靠把合成稿改个标题得到。没有文件路径和复现条件，就继续用 `synthetic`，或者不要发。

## 章节

正式报告和模板都要有这些二级标题，顺序建议保持一致，校验只检查存在：

1. 结论
2. 分析对象与可比性
3. 证据索引
4. 重点问题
5. 对比与维度取舍
6. 建议、取舍与实验
7. 自动巡检如何标记
8. 附录：方法、缺失与声明

重点问题至少三条。模板至少留一条完整骨架。每条都要出现这些字段：证据引用、观察、设计机制、用户成本、业务收益与代价、适用边界、建议、验证方案。

至少一张 Mermaid 图，放旅程或状态。没有可追溯截图时，不使用图片语法，页面用文字线框。

## 主张标记

| 标记 | 含义 |
| :--- | :--- |
| 【事实】 | 能指到仓库文件或当次产物 |
| 【推断】 | 机制假设 |
| 【建议】 | 要做的动作 |
| 【待验证】 | 还不能下结论 |
| 【缺失】 | 数据不存在，保持缺口 |
| 【合成】 | 构造的演示材料 |

正式报告六种标记都要出现。缺某一种，通常说明缺口被写满了，或者建议和事实混在一起。

## 禁止出现的写法

校验会拒绝这些模式：

- 「实测转化率」
- 「淘宝当前」「京东实测」「抖音实测」「美团实测」
- 「转化率提升」后面直接跟数字和百分号
- `GMV` 后面跟加号和数字
- `n =` 后面跟四位及以上数字
- 把默认机型编码写进深度报告
- 图片语法
- 正式报告里残留 `{{` 占位符

业务指标可以写口径、方向和护栏角色。不可以写结果承诺。样本量依赖真实基线时，写【缺失】。

## 自动巡检段落

「自动巡检如何标记」需要写到：拒绝、登录、坐标、基线、证据丢失、弹窗、实验分组。这些词对应日报里的真实限制，不是修辞。

人的判断从证据等级结束的地方开始。等级允许引用时，仍然要由人解释机制、代价和适用边界。等级拒绝时，专题不开。

## 建议与实验

同时给出 P0、P1、P2，以及明确不做项。P0 不是「最大的愿望」，而是证据已经够、且不做会继续污染判断或伤害账号的项。

实验写假设、主指标口径、护栏口径、事件、分群、负向影响、停止与回滚。样本量和周期没有基线就不填。

## 命令

```bash
python analysis_contract.py check docs/examples/深度报告范例-合成演示.md
python analysis_contract.py check --kind template docs/analysis/深度报告模板.md
python -m unittest discover -s tests -t . -v
```

通过只表示最小结构在。发布前仍要人核对证据索引里的每一条路径。

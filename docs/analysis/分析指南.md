# 深度分析指南

这份指南说明什么时候写日报、什么时候开专题，以及一条结论要写到哪一步才算想过，而不是把功能又列了一遍。范例见 `docs/examples/深度报告范例-合成演示.md`。模板和最小校验见同目录另两份文档。

## 先选旅程，再谈竞品

一次专题只深挖一条用户旅程。本仓库里被代码写得最完整的旅程，是从启动到结算预览、并在支付边界停止。默认关键词是洗衣液。它适合讨论「价格能不能被理解」和「优惠状态有没有被改写」，不适合讨论支付成功。

四个已配置的包可以共用这段脚本，不代表它们是同一个任务。货架搜索、内容流里的商品、到家或到店，商业模式不同。比较时只对照同一任务上的机制，例如价格资格是否在决策点闭合、关闭是否改变权益。不把时效绝对值、种草效率和货架点击放进一张加权表。

没有公开的评分锚点时，不打分。将来若要在同一商业模式里排序，权重、锚点和不可比项要写在同一张表上，并做一次敏感性说明：权重翻倍之后排序会不会变。本仓库的范例选择不引入这张表。

## 日报、变化摘要、专题

| 文档 | 何时产生 | 写什么 | 不写什么 |
| :--- | :--- | :--- | :--- |
| 日报 `report.md` | 每次巡检 | 状态、营销命中、证据等级、拒绝推断 | 机制故事、改版建议长文、评分 |
| 变化摘要 | 日报第五节里的一行 | 有哈希或营销文案集合差异时，标记可考虑人工专题 | 把相似度说成改版程度 |
| 深度专题 | 人决定开的时候 | 一条旅程上的少数问题，按模板写完 | 每天一份，或没有证据也写 |

dHash 相似度没有经过标定。它只负责把步骤排进复核队列。Pillow 不可用时，相似度缺失，只比较文件哈希。

## 证据等级

`evidence.py` 读已有目录，不连接设备。三档：

- 可引用，但须附原始文件并遵守限度。
- 只可描述采集标记。可以写工具遇到了什么，不能写用户如何理解页面。
- 拒绝产品推断。目录空，或失败发生在任何截图和 UI 树之前。

这些情况要在专题里单独标出，并停止对应推断：

| 情况 | 停止推断的内容 |
| :--- | :--- |
| 登录或风控阻塞 | 登录之后的页面、实验分组猜测 |
| 弹窗证据丢失 | 弹窗的布局和视觉。日志里的按钮文案仍可引用 |
| 点过「放弃优惠」或授权文案 | 把随后页面当成未被巡检改写的路径 |
| 坐标兜底 | 把落点当成用户选择或信息架构 |
| 支付泛词 | 「支付宝」等词出现过，就说已经进了收银台 |
| 没有基线 | 本期变化、改版、策略转向 |
| 采集失败 | 把没走到的步骤解释成产品没有该能力 |
| 没有实验分组 | 把差异归因到 A/B |

自动观察到标记和文本集合为止。人从这里接手：这个设计可能在为谁省成本，谁在付代价，换到别的商业模式还成不成立。等级不允许引用时，人也不要「根据经验补全」。

## 维度菜单

先从菜单里挑会改变这条旅程决定的项，再删掉没有材料的项。删掉要写原因，避免读者以为是忘了。

可以挑的项：

- 定位、任务、情境、账号和实验组
- 北极星和分解指标的口径
- 信息架构里与这条旅程有关的那几步
- 从发现到完成的关键状态
- 页面层级、组件、文案和信息密度
- 交互反馈、错误、撤销
- 可访问性的验收要求
- 信任、隐私和暗黑模式风险
- 转化与留存的口径，只在观察范围内

经常应该删掉的项：

- 全站信息架构，如果只走了一条路径
- 美观评分和品牌色喜好
- 无障碍「是否合规」的结论，如果没有读屏或取色
- 支付转化和留存曲线，如果采集在支付前停止，或者根本没有行为数据
- 为了表格对称而补上的空泛优缺点

## 一条问题怎么写完

每个重点问题按这个顺序写。跳过任何一环，句子都会退化成「可以更清楚」。

1. 证据引用。给 ID、路径、时间和限制。合成材料要标成合成。
2. 观察。只写看得到的结构和原文。数字要能在材料里复核。
3. 设计机制。解释它为什么可能存在：它把哪一种成本转给了谁，换哪一种经营结果。这是假设，标成推断。
4. 用户成本。落到具体人群和情境，例如非会员、晚上补货、误触后不能撤销。
5. 业务收益与代价。两边都写。只写一边，建议就会变成功能愿望。
6. 适用边界。写出一个不该抄的反例，尤其是商业模式不同的时候。
7. 建议。给改前和改后的文字线框或流程，并写验收条件。
8. 验证方案。假设、主指标口径、护栏口径、事件、分群、负向影响、停止与回滚。样本量、周期、阈值没有真实基线就写【缺失】。

主指标和护栏不能是同一个数的两种心情。例如会员开通率若被当成希望增长的成功，就不能同时当成「跌了就失败」的护栏。允许下降的代价要在实验前登记。

## 和本仓库接上的方式

1. 巡检仍由 `runner.py` 执行。本指南不改变点击、不要求新的抓取。
2. 日报由 `report.py` 生成。先看第五节的等级。
3. 决定开专题后，复制 `深度报告模板.md`。
4. 用 `analysis_contract.py check` 做最小结构检查，再用眼睛核对证据路径。
5. 分享日报和截图之前脱敏。证据等级故意不把 UI 原文再抄一遍，营销清单里仍可能有页面文字，沿用 README 的脱敏要求。

## 不做什么

- 不把澄市、邻时的合成稿改名成真实产品。
- 不在坐标、登录阻塞和泛支付词上写体验优劣。
- 不用精确分数给真实竞品排序。
- 不调用付费接口，也不为了补证据去碰真实账号。缺的证据保持缺失，等下一次授权范围内的采集。

# 新旧差异与最短复用指南

原版没有单独的样例文件。能阅读的最终输出是 `report.py` 的 `generate()`，由 `runner.py` 在巡检结束时调用，也可以离线执行：

```bash
python report.py outputs/<时间戳> --baseline baseline --query "洗衣液"
```

## 原版薄弱在哪里

- 它回答「跑到了哪、抽到了哪些营销词、文件哈希变了没有」，不回答「谁在什么情境里做决定」。
- 建议是三条排障，没有取舍、不做项和可登记的实验口径。
- 视觉差异停在相似度百分比。百分比没有锚点，不能直接叫做改版。
- `device_env.json` 缺字段时，旧逻辑会填上目标机型、固定型号编码 `24030PN60C`、`1440x3200`、DPI 560 和 `OS1.0`。那是文档里的目标设备，不是当次采集。
- 四个商业模式走同一脚本，输出却像四行可以并列的结果。
- 没有「证据不够就停止解释」的位置，读者容易把营销词清单当成体验结论。

## 差异简表

| 项目 | 原版 | 本版 |
| :--- | :--- | :--- |
| 日报 | 环境、状态、截图清单、营销词、哈希和文案差异、排障三条 | 保留，并增加证据等级、拒绝推断、变化线索 |
| 缺失的设备字段 | 填成目标机型 | 写「缺失」 |
| 基线措辞 | 哈希相同会写成画面完全一致；营销文案消失会写成失效 | 只陈述已比较的同名步骤；消失写成「本次未再现」 |
| 深度专题 | 无 | 模板、契约、指南、合成范例 |
| 竞品界面 | 无证据时仍容易被读成已观察 | 无产物则拒绝；范例用澄市、邻时，并标明合成演示 / 非实测 |
| 评分 | 无精确分，但也没有权重禁令 | 仍不打分。若将来使用权重，必须另写锚点和不可比项 |
| 采集行为 | 弹窗词表、坐标、支付停止词 | 不改点击。只在日报和文档里标出风险 |

## 最短复用

1. 读当次日报第五节。出现「拒绝产品推断」或「只可描述采集标记」时，不写体验结论。
2. 只深挖一条旅程。先写任务、人群、情境、版本、平台、时间和账号状态；没有的字段保留【缺失】。
3. 跨产品比较只放同一任务上可比的机制。履约形态不同的对象不进同一评分表。
4. 复制模板。实测把 `evidence_mode` 改为 `measured`，并使用 `EVD-` 编号；没有产物就保持合成，且不要借用真实产品的界面名义。
5. 每条重点问题走完：证据引用、观察、设计机制、用户成本、业务收益与代价、适用边界、建议、验证方案。
6. 建议按影响、证据强度、成本分 P0、P1、P2，并写不做项。实验只写口径。样本量、周期、阈值没有基线就写【缺失】。
7. 运行 `python analysis_contract.py check <报告路径>`。结构通过之后，再由人核对索引里的路径是否真的存在。

日报继续每天生成。深度专题只在变化线索值得看、且证据等级允许引用时另写。
